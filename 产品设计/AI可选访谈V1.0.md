# 知遇 AI 可选访谈 V1.0

日期：2026-11-08。与“轻量建档 V1.0”并列，作为已有问答之后的独立可选模块。

## 产品流程

已有资料和问答形成初始分身 → 用户自主进入“和知遇聊聊” → 规则控制器安排主题 → LLM 自然接话和理解回答 → 保存有来源的普通偏好 → 经授权用于已有 AI 预会面。

访谈不阻断分身使用、不替代原 11 题、不要求答满。会员中心、分身档案和轻量建档页均有入口，页面为 `h5-mvp/interview.html`。沿用现有会员建档权益。

首版四主题：生活与兴趣、沟通方式、个人空间、关系期待。每主题配置主问题、备选问题和兜底追问，可自行选起始主题。支持约 5 分钟或约 15 分钟，实际聊完可以提前结束，任何时候都能暂停、恢复、跳过或结束。暂停不计入时长，也不调用模型；单次操作最多计入 120 秒等待时间，避免后台挂页被计成长访谈。因此计时是体验提醒，非精确在线时长统计。

## 二层职责

控制器位于 `premeet-backend/interviews.py`：选择主题、读取匹配版本的已有问答、控制当前阶段、每个主问题最多追问一次、拒答即换主题、处理预算、保存状态与结束回顾。原 11 题只读不覆盖；轻量选项也可用于帮助访谈接续，访谈接续与对外授权是两个不同使用场景。

LLM 使用已有模型传输服务，一次返回自然接话、追问建议、追问措辞、下个允许主题的措辞、候选原话证据。LLM 不直接改流程状态和使用范围，输出需要通过格式与长度检查。访谈助手身份与会员 AI 分身身份明确区分。

结束回顾由后端根据本次实际涉及主题生成，避免模型凭空生成性格结论。原有分身设置、11 题、会后校准入口继续保留。不新增人格评分、匹配评分、集中画像确认或本人试聊页面。

## 记忆隔离

- 所有会话、消息、证据和调用记录均绑定 `user_id`，会话另有随机 `id`。
- 账户来自服务器验证的登录会话，不能用请求里的 actor 切换数据主人。
- 读取、恢复、修改、删除均同时校验账户和会话；消息与证据关联时也同时匹配用户和会话。
- 每次模型请求重新构造上下文，仅包括本人相关版本化答案、本人普通兴趣和当前会话最近 6 条消息。没有跨用户共享聊天数组、共享模型 thread 或全局摘要。
- 浏览器草稿键包含账户 ID 和会话 ID。历史会话列表只返回本人的记录。
- 账户注销删除访谈会话、消息、证据和模型用量记录。
- 为按用户查询的会话、消息、证据、调用预算建立索引。隔离不依赖模型“记住该属于谁”的提示词。

当前本地服务仍沿用全局数据库锁；并行提交会被串行处理。现有并发请求测试验证隔离正确性，不代表吞吐量测试。生产扩容应采用短事务、异步模型请求和同账户/同会话串行队列；数据库可迁移到 PostgreSQL，保持这些所有权条件。不要为提升并发而将用户上下文放到共享可变缓存中。

## 信息来源与授权

访谈消息完整私密保存。普通偏好证据保留消息 ID、主题和用户原话，使用时再次关联本人原消息校验。模型改写或推测的性格、经历、个人决定不进入可表达事实。

首版采用保守的“完整自述句”筛选：本人明确的普通兴趣或相处偏好可作为证据，例如“我喜欢散步”“我希望先冷静一下再沟通”。保留否定与条件，不能从“不喜欢频繁联系”摘成“喜欢频繁联系”。他人转述、假设、敏感信息和重大决定不自动开放。复杂或无法可靠分类的回答仅保留在私密聊天里，可能造成部分有用信息未被提取；该规则不是完备的语义隐私判别器，应继续评估。

访谈默认私密，用户可在开始前或之后选择允许普通偏好表达。预会面使用必须同时满足：

1. 普通偏好总授权允许；
2. 该次访谈的使用范围允许；
3. 对应证据有效、未删除，且仍能通过原话来源和范围校验。

仅把符合条件的少量普通原话证据放入预会面授权包，不发送完整访谈。访谈、轻量答案和旧 11 题统一在 `refresh_room_twin` 处筛选。访谈使用范围、证据修改或删除后，授权包的访谈修订标识变化，下一轮刷新，并排除旧上下文。已经展示的历史消息不会被撤销删除，正在生成的一条回复不承诺中途取消。

资料修改作为新的本人表达保存，原始消息留存供本人追溯；原证据标为删除。不同语境的答案不覆盖旧问卷，遇到冲突时分身应说明不确定，不擅自挑选结论。复杂冲突识别和主动澄清暂未实现。

## 数据与接口

新增四张表：`interview_sessions`、`interview_messages`、`interview_evidence`、`interview_model_calls`。会话 JSON 包含版本、修订号、阶段、已聊/已跳过主题、追问次数、时长、使用范围、草稿、回顾和模型调用数。

复用 `POST /api/account`，新增 `interview_me`、`interview_start`、`interview_act`；操作包括 message / change / skip / pause / resume / finish / scope / edit_evidence / delete_evidence。修订号检查防止旧标签页覆盖新进度。重复点击开始会复用未结束的本人会话。

所有数据在原库新增表，既有用户、档案、题目答案、分身资料和房间保留。数据库备份：`premeet-backend/backups/before-interview-v1-20261108-233621.sqlite3`，完整性检查通过。备份只在本地；如需恢复，停止服务、再备份当前库后再恢复，恢复备份会舍弃备份之后的数据。

## 模型预算与故障处理

- 每条输入最多 800 字，单次输出最多 600 tokens；接话 60 字、追问 90 字、下题措辞 120 字。
- 当前会话最多 12 次模型请求；每账户滚动 24 小时最多 32 次，失败请求也占用预算。预算用尽仍可使用预设问题保存回答。
- 每个主问题最多一次追问，跳过或拒答后不换说法继续盘问；换掉追问进入下一主题。
- 关闭模型 thinking，12 秒超时，无自动重试；单次只发送当前相关资料和最近 6 条当前会话消息，每条最多 800 字。
- 调用前提交用户回答、调用占用和 pending 记录；成功/失败记录供应商返回的 prompt/completion/total tokens。网络失败或进程退出无法取到用量时保留未知，不记作零。
- 模型失败、返回无效 JSON 或预算不足时，已输入内容不丢，使用固定问题继续。浏览器也保留按用户和会话隔离的未发送草稿。
- 12×600=7200 是每会话的配置输出上限，不含输入，不是总用量上限；每账户滚动日输出配置上限为 32×600=19200。

## 下一步

先人工体验自然度与提取准确性，再决定如何扩展复杂自由表达、冲突澄清、问题治理和并发任务处理。不要自动将所有访谈总结写成可对外表达的事实。

## 2026-11-09 提问控制修订

问题由控制器分配唯一目的，并维护本会话已问清单。开场只提供当前问题；追问与下一主题有各自目标，输出通过主题和去重检查后才能展示。换题会消费新的备选目的并调用模型生成，备选用完则换主题；“回答过了”作为跳过处理。每条新回复展示真实来源，历史消息不伪造来源。具体原因与验收见 `开发记录/AI访谈重复提问修复-20261109.md`。
