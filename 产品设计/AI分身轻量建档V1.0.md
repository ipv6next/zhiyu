# 知遇 AI 分身轻量建档 V1.0

开发日期：2026-11-08。实现分支：`codex/lightweight-twin-v1`。

## 定位和入口

约 5 分钟建立初始分身，不要求答满固定题数，不增加画像集中确认、本人分身试聊或强制深度访谈。会员中心、原分身档案提供“轻量建档”入口，页面为 `h5-mvp/light-twin.html`。沿用现有产品权益：分身建档由会员使用，候选真人不需要会员权益即可按现有规则进入已授权分身。

首版固定 8 个候选问题，每类 2 个：生活与兴趣、个人特点、相处方式、关系期待。优先覆盖不同主题，再提供同类补充。支持选择、自由输入、换题、跳过整个主题、暂停、恢复和随时结束。同一主问题最多追问一次，重新回答也不增加追问次数。原 11 题仍为独立版本化题库，可选补充，保留历史答案和版本。

## 信息与表达边界

| 信息 | 保存方式 | 普通授权后的预会面使用 |
| --- | --- | --- |
| 本人选择的普通偏好 | 原答案、题号、版本、来源、时间 | 允许，后端再次校验选项来源 |
| 明确的短日常兴趣自述 | 原文私密保存，另存精确摘录 | 仅摘录可用，例如“我喜欢徒步”→“喜欢徒步” |
| 其他自由输入和追问回答 | 原文私密保存，可查看、重答、删除 | 首版默认不对外使用 |
| 原 11 题 | 原答案不变 | 同一普通授权控制；仅从匹配版本的本人选项重建表达，不信任旧缓存摘要 |
| 旧会后校准自由文本、旧手填相处方式 | 原档案保留，原入口可修改；轻量页面显示旧校准记录 | 尚未分类，不随普通授权自动开放 |
| 模型追问或推断 | 追问只用于访谈引导 | 不作为本人事实或个人决定 |
| 已公开基本资料 | 沿用现有档案 | 分身使用姓名、城市、年龄段、性别、身高、学历的有限白名单 |

短兴趣摘录采用完整句匹配及有限词表，不靠模型自行判断可以公开。否定句、混合隐私、指令文本和复杂叙述不通过。当前支持徒步、散步、跑步、游泳、骑行、健身、运动、做饭、烘焙、看书、阅读、看电影、看展、听音乐、画画、摄影、旅行、园艺、桌游。此范围有意保守；复杂自由输入不会自动变成丰富的对外画像，是下一版可改进项。

## 授权和撤回

首次开启预会面前，分身主人必须选择“允许使用普通偏好”或“暂不允许”。没有默认选中，不同意仍可使用基本公开资料开展预会面。该选择不等同于现有的预会面总开关，两个设置分别生效。

后端在每次回复前刷新可表达资料，统一处理轻量偏好和旧 11 题。撤回后，下次回复不再加载这些内容；授权版本变化时，从模型上下文排除变化前的聊天历史，且后续不回放旧 AI 回复，降低通过旧回复重新引入信息的风险。已经展示给对方的历史消息不会被撤回删除。已开始生成的一条回复不承诺中途取消；撤回成功后的后续请求使用新范围。

候选人页面继续明确 AI 分身身份。模型以第一人称自然交流，但信息不足需明确不确定；不得编造经历、推断敏感事实或代作重大决定。模型守则并非绝对质量保证，仍需持续评估输出。

## 后端状态和成本

新增 `twin_light_interviews`、`twin_light_facts`、`twin_expression_consent` 三张表；不重写旧用户档案、分身档案、题目或房间。账号注销同步删除新增数据。

状态包括题目版本、当前题、主问题/追问阶段、完成题、跳过主题、暂停状态、草稿、修订号、回答历史、已追问题和模型用量。接口受登录会话和会员权益控制，以会话确定数据主人，不信任请求中伪造的 actor。修订号拒绝旧标签页覆盖新进度。

`POST /api/account` 增加 `light_me`、`light_act`、`light_delete_fact`、`expression_consent`。操作支持 answer / next / change / skip_topic / pause / resume / finish / revisit。

- 每条输入最多 600 字；追问输出最多 120 tokens，并校验不超过 120 字。
- 一个建档状态终身最多 8 次模型请求，包括失败请求；不因暂停、刷新、重答而归零。
- 每次只发送当前主问题和当前回答，不发送整个访谈原文、其他用户档案或旧房间聊天。
- DeepSeek 复用统一传输模块；建档追问关闭 thinking，12 秒超时，无自动重试。
- 每次请求保存 pending / ok / failed 状态，记录供应商返回的 prompt / completion / total tokens；返回了用量但没有有效文本时仍保留用量。
- 网络中断或进程退出导致无供应商用量时标记 unknown，不将其当作零成本。120 × 8 = 960 只是输出配置上限，输入另计，不能视为总 token 上限。
- 模型调用前先提交用户答案和调用占用；失败保留答案，使用可跳过的固定追问继续。浏览器也保留按账号隔离的草稿。

当前沿用本地服务全局数据库锁；一次追问调用期间其他数据库请求可能等待最多约 12 秒。生产部署前应改为异步任务/短事务，不将当前实现视为并发生产架构。

数据库通过 SQLite backup API 备份为 `premeet-backend/backups/before-lightweight-v1-20261108-132511.sqlite3`，完整性检查通过，原库 6 个账户。使用新代码首次打开数据库只增加新表。

需要恢复时，先停止 4180 服务并再次备份当前库，再将指定备份复制为 `premeet-backend/sessions.sqlite3`。不要在服务运行中替换数据库。恢复旧备份会失去备份之后的数据，应先确认恢复时间点；通常代码回退即可，新增表可保留。备份含私人信息，保持本地，不上传 GitHub。
