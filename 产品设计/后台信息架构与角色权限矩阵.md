# 知遇运营后台：信息架构与角色权限矩阵 V1

状态：已确认，作为后台第一期实现范围。  
定位：仅供平台运营、审核和人工服务人员使用的桌面网页；不面向普通用户开放。

## 一、第一期信息架构

1. **运营总览**：用户、会员、预会面、待处理安全事项等关键指标与待办队列。
2. **用户与档案**：分页查询、资料完整度、会员权益、账号状态、来源、最小化档案查看。
3. **认证与审核**：实名、照片一致性、学历等状态；人工核验队列与处理记录。
4. **推荐与预会面**：推荐解释、双向意愿、预会面房间状态、真人继续决定、异常关闭。
5. **安全与投诉**：举报、拉黑关联、敏感内容、冻结/解冻、人工协助与处置时限。
6. **数字分身与题库**：分身完整度、会后校准、题库版本、候选题审核与发布记录。
7. **角色与权限**：人员、角色、数据范围、敏感操作的二次确认与审计。
8. **系统设置**：仅超级管理员可操作的基础配置与系统审计。

## 二、角色权限

| 角色 | 可访问范围 | 不可访问范围 | 关键动作 |
|---|---|---|---|
| 超级管理员 | 全站数据与配置 | 无，但高风险操作须审计 | 角色授权、冻结/解冻、导出审批、系统配置 |
| 运营专员 | 用户基础资料、推荐和运营队列 | 身份证原件、精确地址、完整私密聊天 | 资料审核、推荐运营、触达任务 |
| 安全审核员 | 认证、举报、异常房间所需信息 | 与案件无关的用户数据 | 风险判定、冻结建议、工单闭环 |
| 红娘顾问 | 被分配且获授权的用户、服务摘要 | 全站用户池、未授权私密资料 | 真人继续协助、服务群跟进、关系复盘 |

## 三、数据与操作原则

- 最小权限：只展示完成当前任务所必需的数据。
- 用户来源、授权范围、审核结果、关键操作均须可追溯。
- 冻结、解冻、导出、修改核验结论、查看原始聊天内容属于高风险操作：需二次确认与审计记录。
- 前端隐藏菜单不构成权限控制；后端 API 必须校验角色、数据归属和操作范围。
- 会员资料、AI 分身与预会面内容不因运营方便而默认向红娘开放。

## 四、实施顺序

1. 搭建管理端框架、登录与角色权限骨架。
2. 用户/档案/会员权益及冻结拦截。
3. 认证审核、安全工单与审计日志。
4. 推荐、预会面与真人服务群的运营视图。
5. 数字分身与题库治理。

## 五、技术边界

- 前端：React + TypeScript + Ant Design Pro 组件体系。
- 后端：FastAPI，提供受服务端权限控制的 API。
- 当前本地原型的 Python `http.server` 只用于演示，不得直接公开部署。
- 本地开发可使用 SQLite；真实试点前迁移至 PostgreSQL。
